# Stitch 수정 프롬프트: 운동 최종 (사용성 점검 후, 2026-11-21)

에뮬레이터 앱 WebView에 실제 HTML(_27, _28, _29)을 띄워 직접 눌러 보고 입력해 본 결과:
- 360dp 화면에서 "입력칸 + 버튼" 줄이 모두 화면 밖으로 넘침(부위 추가 19px, 단백질 추가 40px). flex-1 입력칸에 min-w-0이 없어서 줄어들지 않고,
  단백질 g 칸(w-24)이 대신 42px까지 눌림. 앞서 "넘침 없음"으로 잰 것은 페이지 폭(넘친 만큼 넓어짐) 기준이라 틀렸음.
- 운동을 펼치면 "운동 이름" 칸이 맨 위라 세트 표가 아래로 밀림. 이름 바꾸기는 가끔이고 세트 입력은 매번이므로 세트 표를 맨 위로.
- 세트 숫자 칸을 누르면 커서가 기존 숫자 사이에 들어가 "60" 뒤에 "62.5"를 치면 "662.50"이 됨 → 디자인이 아니라 앱 코드에서 "누르면 숫자 전체 선택"으로 처리(구현 때).

운동 화면 3장("운동 - 운동 관리", "운동 - 단백질 기록", "운동 - 상태 모음")을 마지막으로 아래 두 가지만 고쳐 주세요. 그 밖의 class·문구·순서는 한 글자도 바꾸지 마세요. 다른 앱 화면은 절대 건드리지 마세요. 출력 형식은 지난번과 같습니다.
[1. 360px 폭에서 줄이 화면 밖으로 넘치는 문제] 실제 휴대폰 360px 폭에서 "부위 추가", "운동 추가", "단백질 추가" 줄의 버튼이 카드 밖으로 밀려 나갑니다. 세 화면의 모든 "입력칸 + 버튼" 한 줄에서:
- flex-1 입력칸 class 끝에 min-w-0 을 붙여 주세요(줄어들 수 있게).
- 버튼 class 끝에 shrink-0 을 붙여 주세요.
- 단백질 칸을 감싼 div class="relative w-24" 는 class="relative w-24 shrink-0" 으로 바꿔 주세요.
[2. 펼친 운동 안의 순서] 운동 중에 바로 세트를 적을 수 있게, "운동 - 운동 관리"의 펼친 "벤치프레스"와 "운동 - 상태 모음" ③의 펼친 운동 안 순서를 이렇게 바꿔 주세요(각 덩어리의 HTML과 class는 그대로, 위치만 이동):
세트 표 → "+ 세트 추가" → 메모 (선택) → 운동 이름 → "기록 저장" → 이전 기록 → 운동 삭제
