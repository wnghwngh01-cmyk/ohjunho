# Stitch 프롬프트: 광장 화면 (2026-11-20)

아래 구분선 사이 전체를 Stitch에 그대로 보낸다. 가계부 때와 같은 방식이고, 화면 2장(발견 탭, 앱 개선 탭)을 요청한다.

---

[목적]
이 프로젝트에서 이미 완성한 "오늘", "캘린더", "더보기", "가계부" 화면과 같은 앱 "하루를 담다"의 **광장 화면**을 만들어 주세요.
새 앱을 디자인하는 것이 아닙니다. 이미 작동하는 기능의 **화면 디자인만** 바꾸는 작업입니다.
아래에 적힌 기능과 항목만 정확히 그려 주세요. 적혀 있지 않은 기능, 버튼, 메뉴, 탭은 절대 추가하지 마세요.
화면은 2장입니다: ① "광장 - 발견" (게시물 목록), ② "광장 - 앱 개선" (개선 제안 게시판).

[앱과 화면 위치]
- 앱: "하루를 담다" (안드로이드 앱, 휴대폰 세로 화면 전용, 한국어)
- 이 화면으로 오는 길: 하단 탭바의 네 번째 탭 "광장", 또는 더보기 → 관리 → "광장"
- 하단 탭바(오늘 · 캘린더 · 가계부 · 광장 · 더보기)는 앱에 이미 있으므로 **그리지 마세요.** 화면 아래쪽에 탭바가 덮을 96px 여백만 남겨 주세요.
- 이 화면의 역할: 사용자가 자기 기록·일기·독서록을 골라서 공개하거나 짧은 자유글을 올리고, 다른 사용자의 공유글을 보고 좋아요·댓글·팔로우를 하는 선택형 커뮤니티입니다. 개인 기록은 기본 비공개이고, 여기에는 사용자가 직접 공유한 것만 보입니다.

[머리글 규칙: 중요]
- 화면 맨 위에 "광장" 같은 **페이지 제목을 넣지 마세요.**
- **알림 종(알림함) 버튼도 넣지 마세요.** 알림함은 오늘 화면에만 있습니다.
- 화면은 바로 아래 1번 탭부터 시작합니다.

[디자인 기준: 이미 만든 4개 화면과 똑같이]
- 오늘·캘린더·더보기·가계부 화면의 디자인 시스템을 그대로 씁니다. 새로운 색, 새로운 카드 모양, 새로운 글꼴을 만들지 마세요.
- 바탕 #FAF9F6, 카드 흰색 #FFFFFF + 테두리 1px #F0EFEA(또는 #E9E8E5), 카드 모서리 rounded-2xl(16px), 그림자는 아주 옅게(0 2px 8px rgba(0,0,0,0.025))
- 주색 숲녹색 #1E3A2F(버튼, 선택된 상태), 진한 숲녹색 #162C23(눌림), 연한 녹색 배경 #E8F1EC / #EBF7F0, 민트 배지 #C3ECD6 / 글자 #133E2B
- 글자: 기본 #1A1C1A, 보조 #424844, 흐린 글자 #8E928F
- 신고·차단·내리기·삭제 같은 경고 계열: 코랄 #B45650 (연한 배경 #FDF0EE, 연한 테두리 #FAD4D1)
- 그 밖의 배지 색이 필요하면 캘린더에서 쓴 색만 사용: 민트 #EBF7F0/#1E3A2F, 스틸블루 #EDF3F8/#4E70A0, 앰버 #FEF6EC/#C97A1E, 코랄 #FDF0EE/#B45650
- 글꼴: Pretendard(없으면 Noto Sans KR)
- 아이콘: 다른 화면과 같은 선 아이콘(lucide 스타일, stroke 1.5, 둥근 끝), 인라인 SVG
- 폭: 390px 기준, 콘텐츠 최대 폭 480px, 좌우 여백 16px. 360px에서도 글자나 버튼이 잘리거나 두 줄로 꺾이지 않게.
- 버튼·탭·칩처럼 누르는 것은 최소 44px 높이의 터치 영역(보이는 크기가 작으면 여백으로 확보)

[화면 ① 광장 - 발견: 위에서부터 이 순서대로, 이 내용만]

1. 탭 3개 (가계부의 지출/수입 전환과 같은 모양의 3칸 전환 버튼)
   - "발견" (선택됨) · "팔로잉" · "앱 개선"
   - 팔로잉 탭은 발견 탭과 같은 화면 구성이고, 내가 팔로우한 사람의 글만 보입니다.

2. 자유글 쓰기 (접히는 칸, 기본 닫힘, 가계부의 "기록 검색" 접힘과 같은 모양)
   - 접힌 제목: "광장에 자유글 쓰기"
   - 펼치면: 여러 줄 입력칸(placeholder "함께 나누고 싶은 이야기를 적어보세요.", 최대 6000자) + "자유글 올리기" 버튼(숲녹색)
   - 분류에서 "대장간"을 고른 동안에는 이 칸이 보이지 않습니다.

3. 분류 칩 한 줄 (가계부 분류 칩과 같은 모양, 하나만 선택, 가로로 넘치면 가로 스크롤)
   - 전체(선택됨) · 기록 · 일기 · 독서록 · 자유글 · ⚔️ 대장간

4. 게시물 카드 목록 (카드 한 장 = 게시물 하나)
   카드 안 구성(위에서부터):
   - 작성자 줄: 왼쪽 원형 프로필 사진(사진이 없으면 이름 첫 글자), 그 옆에 이름(굵게, 누르면 그 사람의 공개 프로필로 이동) + 이름 옆 작은 칭호 배지(예: "새벽 기록가", 없을 수도 있음), 이름 아래 작은 글씨 연구실 이름(예: "민서의 연구실"). 오른쪽 끝에 "팔로우" 버튼(팔로우 중이면 "팔로잉"으로 바뀌고 채워진 모양). 내 글에는 팔로우 버튼이 없습니다.
     - 프로필 사진에는 사용자가 고른 장식 테두리가 둘러질 수 있으니 사진 주변에 약간의 여유를 두세요.
   - 사진(있을 때만): 1~4장 격자. 5장 이상이면 네 번째 칸 위에 "+N". 사진을 누르면 크게 봅니다.
   - 종류 배지 한 줄: "기록" / "일기" / "독서록" / "자유글" / "대장간" 중 하나. 독서록이면 배지 옆에 "한강 지음"처럼 저자.
   - 제목(굵게). 자유글에는 제목이 없습니다.
   - 본문: 길면 몇 줄에서 자르고 끝에 "더보기" 글자 버튼. 본문 아래 작은 글씨로 작성 시각(예: "11. 20. 오후 03:12").
   - 동작 줄(왼쪽부터): 좋아요 버튼(하트 아이콘 + 숫자, 누르면 채워진 하트), 댓글 버튼(말풍선 아이콘 + 숫자 + 작은 아래 화살표), 공유 버튼(아이콘 + "공유", 링크 복사), 오른쪽 끝 "···" 더보기 메뉴.
     - "···"를 누르면 작은 메뉴: 내 글이면 "내리기"(코랄) 하나, 남의 글이면 "신고"와 "차단"(코랄).
   - 댓글 영역(댓글 버튼을 누르면 그 카드 안에서 아래로 펼쳐짐):
     - 댓글 한 줄: 작은 원형 프로필 사진, 이름 + 칭호 배지, 작성 시각, 내용. 답글은 한 단계 들여쓰고 내용 앞에 "@이름"(굵게).
     - 각 댓글 아래 작은 글자 버튼: "답글", 그리고 내 댓글이면 "삭제"(코랄) / 남의 댓글이면 "신고".
     - 맨 아래 입력 줄: 입력칸(placeholder "댓글을 입력하세요") + "등록" 버튼(숲녹색, 작게).
     - 댓글이 없으면 "첫 댓글을 남겨보세요."
   - 대장간 글(종류 "대장간")은 제목·본문 자리에 "검 강화 증명서" 카드가 들어갑니다. 이 증명서와 검 그림은 나중에 따로 디자인해서 넣을 것이니 **절대 직접 그리지 마세요.** 그 자리에는 점선 테두리의 빈 상자(높이 약 160px)와 가운데 작은 회색 글자 "대장간 증명서 자리"만 넣어 주세요. 대장간 글의 좋아요 버튼은 하트 옆에 "👍 멋져요"(부고 글이면 "🌼 헌화하기") 글자가 붙습니다.
   - 목록이 비었을 때 문구: 발견 "아직 광장에 공유된 내용이 없습니다." / 팔로잉 "팔로우한 연구실의 새 공유가 아직 없습니다."

   이 화면에 보여 줄 예시 카드(이 순서로 4장):
   (가) 사진 3장이 있는 "기록" 글, 남의 글, 팔로우 안 한 상태, 칭호 배지 있음
   (나) "독서록" 글, 저자 표시, 팔로잉 상태, 댓글 영역이 펼쳐진 상태(댓글 2개 + 답글 1개 + 입력 줄)
   (다) 본문이 길어서 "더보기"가 붙은 "자유글", 내 글(팔로우 버튼 없음), "···" 메뉴가 펼쳐져 "내리기"가 보이는 상태
   (라) "대장간" 글, 빈 증명서 자리 상자 + "👍 멋져요" 좋아요

[화면 ② 광장 - 앱 개선: 1번 탭에서 "앱 개선"이 선택된 상태]

1. 탭 3개 (화면 ①과 같고, "앱 개선"이 선택됨)
2. 안내 상자(연한 코랄 또는 연한 앰버 배경의 작은 상자): "보안상 민감한 버그는 공개되는 개선 제안에 쓰지 말고, **더보기 > 버그 제보**에서 알려 주세요."
3. 개선 제안 쓰기 (접히는 칸, 기본 닫힘, 화면 ①의 자유글 쓰기와 같은 모양)
   - 접힌 제목: "개선 제안 쓰기"
   - 펼치면: 제목 입력(placeholder "어떤 점이 더 좋아졌으면 하나요?", 최대 120자), 설명 여러 줄 입력(placeholder "사용 중 불편했던 상황이나 원하는 동작을 알려주세요.", 최대 3000자), "제안 올리기" 버튼(숲녹색)
4. 제안 목록 (카드 한 장 = 제안 하나)
   - 왼쪽: 추천 버튼(세로로 위쪽 삼각형 "△" + 숫자, 내가 추천했으면 채워진 숲녹색 모양)
   - 오른쪽: 제목(굵게), 설명(여러 줄), 아래 줄에 상태 배지 + 작은 글씨 "작성자 이름 · 작성 시각"
   - 상태 배지 5가지(정확히 이 문구): "제안됨"(회색) · "검토 후 계획"(스틸블루) · "개발 중"(앰버) · "반영 완료"(민트/숲녹색) · "보류"(회색)
   - 목록이 비었을 때: "첫 개선 제안을 남겨보세요."
   이 화면에 보여 줄 예시: 제안 3개(상태 "반영 완료" 1개, "개발 중" 1개, "제안됨" 1개, 그중 1개는 내가 추천한 상태)

[하지 말 것]
- 페이지 제목("광장")과 알림 종 버튼을 넣지 마세요.
- 대장간 증명서·검 그림·인증서 모양을 그리지 마세요(빈 자리 상자만).
- 위 목록에 없는 기능을 넣지 마세요: 검색창, 글쓰기 플로팅 + 버튼, 인기 순위, 해시태그, 스토리, 북마크/저장, DM·채팅, 이모지 반응 여러 개, 조회수, 정렬 메뉴, 다른 탭 추가 등 모두 금지.
- 하단 탭바, 상태바, 휴대폰 틀을 그리지 마세요.
- 다크 모드는 만들지 마세요.
- "데이터 초기화", "데모" 같은 시연용 버튼을 넣지 마세요.
- 탭·분류·버튼·상태 배지 문구를 바꾸지 마세요(위에 적힌 한국어 그대로).
- 다른 화면(오늘·캘린더·더보기·가계부)의 디자인은 바꾸지 마세요.

[출력 형식: 반드시 이 방식으로]
- 결과물은 화면마다 **정적 HTML 파일 한 개(code.html) + 화면 이미지(screen.png)** 로, 화면 2장(① 발견, ② 앱 개선)을 각각 만들어 주세요.
- code.html 규칙:
  - Tailwind CSS(CDN) + 같은 파일 안의 tailwind.config로 위 색을 토큰으로 정의
  - **JavaScript로 화면을 그리지 마세요.** 모든 카드와 줄을 HTML 마크업으로 직접 적어 주세요. 데이터 배열 + 렌더 함수 방식, React, JSON 명세 방식은 쓰지 않습니다.
  - 접히는 칸은 `<details>` / `<summary>` 로 만들어 주세요(스크립트 없이 열리고 닫히게). "···" 메뉴도 `<details>`로 만들어 주세요.
  - `style="..."` 속성을 쓰지 말고 색·크기는 Tailwind 클래스로만 지정하세요.
  - 버튼 글자는 줄바꿈되지 않게 해 주세요(짧은 글자 버튼에 whitespace-nowrap).
  - 예시 사진은 회색 단색 상자(bg 색 클래스)로 대신하고 외부 이미지 주소를 쓰지 마세요.
  - 예시 데이터는 현실적인 한국어 값으로.
- 위 형식이 왜 필요한지: 이 HTML을 앱에 글자 그대로 옮기고, 버튼 동작과 실제 데이터만 연결합니다. 그래서 HTML 구조가 곧 최종 화면이 됩니다.
