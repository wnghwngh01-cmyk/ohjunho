# Stitch 프롬프트: 운동 화면 (2026-11-21)

아래 구분선 사이 전체를 Stitch에 그대로 보낸다. 가계부·광장 때와 같은 방식이고 화면 2장(운동 관리, 단백질 기록)을 요청한다.
목적: 운동 중 한 손으로 빠르게 세트를 적고, 지난번 기록을 보고 따라 할 수 있게 하는 것.

---

[목적]
이 프로젝트에서 이미 완성한 "오늘", "캘린더", "더보기", "가계부", "광장" 화면과 같은 앱 "하루를 담다"의 **운동 화면**을 만들어 주세요.
새 앱이 아니라, 이미 작동하는 기능의 **화면 디자인만** 바꾸는 작업입니다. 아래 기능과 항목만 정확히 그리고, 적혀 있지 않은 기능은 추가하지 마세요.
가장 중요한 목표: **운동하는 도중에 한 손으로 쉽게 쓰는 것.** 숫자 입력칸과 버튼은 크고 누르기 쉽게, 지금 할 일(세트 적고 저장)이 가장 눈에 띄게.
화면은 2장입니다: ① "운동 - 운동 관리", ② "운동 - 단백질 기록".

[앱과 화면 위치]
- 앱: "하루를 담다" (안드로이드 앱, 휴대폰 세로 화면 전용, 한국어)
- 이 화면으로 오는 길: 더보기 → "운동 기록", 또는 오늘 화면의 단백질 카드 → "단백질 기록"(이때는 ② 단백질 탭이 열림)
- 하단 탭바(오늘 · 캘린더 · 가계부 · 광장 · 더보기)는 앱에 이미 있으므로 **그리지 마세요.** 아래쪽에 탭바가 덮을 96px 여백만 남겨 주세요.
- 이 화면의 역할: 사용자가 "가슴", "등", "하체"처럼 직접 만든 부위 안에 운동을 넣고, 운동마다 세트(무게 kg × 횟수)를 적어 저장합니다. 저장할 때마다 그날 기록이 "이전 기록"으로 쌓여서 다음에 참고합니다. 또 날짜별로 먹은 단백질(g)을 기록합니다.

[머리글 규칙: 중요]
- 화면 맨 위에 "운동 기록" 같은 **페이지 제목을 넣지 마세요.** 알림 종(알림함) 버튼도 넣지 마세요(알림함은 오늘 화면에만 있습니다).
- 화면은 바로 아래 1번 탭부터 시작합니다.

[디자인 기준: 이미 만든 화면들과 똑같이]
- 오늘·캘린더·더보기·가계부·광장 화면의 디자인 시스템을 그대로 씁니다. 새로운 색, 카드 모양, 글꼴을 만들지 마세요.
- 바탕 #FAF9F6, 카드 흰색 + 테두리 1px #F0EFEA, 모서리 rounded-2xl, 그림자 shadow-subtle(0 2px 8px rgba(0,0,0,0.025))
- 주색 숲녹색 #1E3A2F(버튼, 선택 상태), 눌림 #162C23, 연한 녹색 #E8F1EC / #EBF7F0, 민트 배지 #C3ECD6 / 글자 #133E2B
- 글자: 기본 #1A1C1A, 보조 #424844, 흐림 #8E928F. 입력칸 테두리 #E9E8E5, 입력칸/옅은 칸 배경 #FAF9F6 또는 #F4F3F0
- 삭제 계열: 코랄 #B45650 (연한 배경 #FDF0EE)
- 글꼴 Pretendard, 숫자는 tabular-nums. 아이콘은 다른 화면과 같은 선 아이콘(lucide 스타일, stroke 1.5), 인라인 SVG
- 폭 390px 기준, 콘텐츠 최대 480px, 좌우 여백 16px. 360px에서도 잘리거나 꺾이지 않게.
- 누르는 것은 모두 최소 44px 높이. 세트의 무게·횟수 입력칸은 특히 크게(높이 44px 이상, 숫자 크게, 가운데 정렬).

[화면 ① 운동 - 운동 관리: 위에서부터 이 순서대로, 이 내용만]

1. 탭 2개 (가계부의 지출/수입 전환과 같은 모양)
   - "운동 관리"(선택됨) · "단백질 기록"

2. 부위 카드 목록 (카드 한 장 = 부위 하나, 접히는 칸, 여러 개 동시에 펼칠 수 있음)
   - 접힌 머리 줄: 부위 이름(굵게, 예 "가슴") + 작은 글씨 "운동 3개" + 오른쪽 아래 화살표
   - 펼치면 안에 운동 목록(운동 한 줄 = 접히는 칸):
     - 접힌 운동 줄: 운동 이름(예 "벤치프레스") + 작은 글씨 요약 "3세트 · 60kg × 10회"(가장 무거운 세트) + 아래 화살표
     - 펼친 운동(편집 상태):
       a. 운동 이름 입력칸(이름을 고칠 수 있음, 최대 80자)
       b. 세트 표: 머리 줄 "세트 · 무게(kg) · 횟수", 그 아래 세트 줄들. 한 줄 = 세트 번호(1, 2, 3…), 무게 입력칸(소수 가능, 예 62.5), 횟수 입력칸(정수), 줄 끝에 작은 × 삭제 버튼. 세트는 최소 1개.
       c. "+ 세트 추가" 버튼(옅은 테두리 버튼, 표 바로 아래 전체 폭). 누르면 마지막 세트의 무게·횟수가 복사된 새 줄이 생깁니다.
       d. 메모 입력칸(한 줄, placeholder "메모 (선택) · 예: 다음에는 마지막 세트 10회", 최대 500자)
       e. "기록 저장" 버튼(숲녹색, 전체 폭, 가장 눈에 띄게)
       f. 그 아래 한 줄: 왼쪽 "이전 기록" 글자 버튼(누르면 아래로 펼쳐지는 표시, 화살표), 오른쪽 "운동 삭제" 글자 버튼(코랄, 작게)
       g. 이전 기록(펼쳤을 때): 최근 저장 10개까지, 한 줄 = 날짜 시각(예 "11. 18. 오후 07:40") + 세트 칩들("60kg×10" "60kg×8" "55kg×10"). 없으면 "저장된 이전 기록이 없습니다."
   - 운동 목록 아래: 운동 추가 줄 = 입력칸(placeholder "운동 이름") + "추가" 버튼
   - 부위 카드 맨 아래 오른쪽에 작은 "부위 삭제" 글자 버튼(코랄). 누르면 앱이 확인을 묻습니다(확인 창은 그리지 마세요).

3. 부위 추가 (목록 맨 아래, 점선 테두리의 옅은 카드)
   - 입력칸(placeholder "새 부위 이름 · 예: 어깨", 최대 60자) + "부위 추가" 버튼(숲녹색)

4. 부위가 하나도 없을 때: 카드 안 가운데 "아직 만든 부위가 없습니다." + 작은 글씨 "가슴, 등, 하체처럼 원하는 이름으로 추가해 보세요." (그 아래 3번 부위 추가 카드는 그대로)

   이 화면에 보여 줄 예시:
   - 부위 "가슴"(펼침): 운동 "벤치프레스"(펼침, 세트 3개: 60×10, 60×8, 55×10, 메모 있음, 이전 기록 펼침 2개), 운동 "인클라인 덤벨프레스"(접힘, 요약 "3세트 · 22.5kg × 12회"), 운동 "케이블 플라이"(접힘)
   - 부위 "등"(접힘, "운동 4개")
   - 부위 "하체"(접힘, "운동 2개")
   - 맨 아래 부위 추가 카드

[화면 ② 운동 - 단백질 기록: 1번 탭에서 "단백질 기록"이 선택된 상태]

1. 탭 2개 (화면 ①과 같고 "단백질 기록"이 선택됨)
2. 날짜 이동 줄: 왼쪽 ‹ 버튼(전날), 가운데 날짜 "11월 21일 (토)"(누르면 달력에서 날짜 선택), 오른쪽 › 버튼(다음 날). 버튼은 44px.
3. 합계 카드: 작은 글씨 "오늘 섭취량"(다른 날이면 "11월 20일 섭취량") + 큰 숫자 "92.5 g"(숲녹색, 굵게)
4. 추가 줄(한 줄): 음식 이름 입력칸(placeholder "음식 이름 (선택)", 넓게) + 단백질 입력칸(placeholder "단백질(g)", 좁게, 소수 가능) + "추가" 버튼(숲녹색)
5. 그날 기록 목록(카드 하나 안의 줄들): 한 줄 = 음식 이름(없으면 "단백질") + 오른쪽 "30 g" + 작은 "삭제" 글자 버튼(코랄). 최근에 넣은 것이 위.
6. 기록이 없을 때: "이 날짜에는 아직 기록이 없습니다."

   이 화면에 보여 줄 예시: 오늘, 기록 4개(닭가슴살 30g, 프로틴 쉐이크 25g, 계란 2개 12.5g, 그릭요거트 25g), 합계 92.5 g

[하지 말 것]
- 페이지 제목과 알림 종 버튼을 넣지 마세요.
- 위에 없는 기능을 넣지 마세요: 운동 타이머, 휴식 타이머, 루틴 시작 버튼, 그래프/통계, 1RM 계산, 칼로리, 단백질 목표치·진행 막대, 체중 기록, 검색, 공유, 플로팅 + 버튼, 다른 탭 추가 등 모두 금지.
- 하단 탭바, 상태바, 휴대폰 틀을 그리지 마세요. 다크 모드도 만들지 마세요.
- 탭·버튼·문구를 바꾸지 마세요(위 한국어 그대로).
- 다른 화면의 디자인은 바꾸지 마세요.

[출력 형식: 반드시 이 방식으로]
- 화면마다 **정적 HTML 파일 한 개(code.html) + 화면 이미지(screen.png)**, 화면 2장(① 운동 관리, ② 단백질 기록).
- code.html 규칙:
  - Tailwind CSS(CDN) + 같은 파일 안 tailwind.config로 위 색을 토큰으로 정의
  - **JavaScript로 화면을 그리지 마세요.** 모든 카드와 줄을 HTML 마크업으로 직접 적어 주세요(데이터 배열 + 렌더 함수, React, JSON 명세 방식 금지).
  - 접히는 칸(부위, 운동, 이전 기록)은 `<details>` / `<summary>`로(스크립트 없이 열리고 닫히게).
  - 입력칸은 실제 `<input>`(무게는 type="number" inputmode="decimal", 횟수는 inputmode="numeric").
  - `style="..."` 속성 금지, 색·크기는 Tailwind 클래스로만. 짧은 버튼 글자는 whitespace-nowrap.
  - 예시 데이터는 현실적인 한국어 값으로.
- 이 형식이 필요한 이유: 이 HTML을 앱에 글자 그대로 옮기고 버튼 동작과 실제 데이터만 연결합니다. HTML 구조가 곧 최종 화면입니다.
